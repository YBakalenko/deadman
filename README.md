# deadman

«Мёртвая рука» для сервера на домашнем роутере **Keenetic с Entware**.

Репозиторий: <https://github.com/YBakalenko/deadman>

Сервер сам не может сообщить, что он умер целиком: вместе с ним умирает и
его система оповещения. deadman переворачивает задачу. Сервер регулярно
шлёт на роутер короткий сигнал «жив». Если сигнала нет дольше заданного
времени, роутер пишет в Telegram. Когда сигнал вернулся, он пишет ещё раз.
Заодно роутер может сам проверять, отвечают ли снаружи нужные адреса.

```
 сервер ──(раз в 1–5 мин: GET/POST https://…/beat/<ключ>)──▶ KeenDNS ──▶ роутер
                                                                         │
                       сторож раз в минуту: сигнал свежий? адреса отвечают?
                                                                         │
                                         нет ──▶ 🔴 Telegram    снова да ──▶ 🟢 Telegram
```

## Что умеет

- Принимает сигнал «жив» на `/beat/<ключ>`, методом GET или POST (с любым
  телом, например вебхук Alertmanager). Чужой ключ получает 404.
- Тревожит, если сигнала нет дольше `BEAT_TIMEOUT_MIN` минут, и сообщает,
  когда он вернулся и сколько длился сбой.
- Проверяет адреса из `CHECK_URLS`. Тревога — после `URL_FAILS` неудач
  подряд: одиночный сбой сети её не вызовет.
- **Не поднимает ложных тревог из-за своего интернета.** Пока у роутера нет
  сети, проверки отложены, а после её возвращения отсчёт начинается заново.
  Так же и после перезагрузки роутера.
- Если Telegram не ответил, сообщение не теряется: оно ждёт в очереди и
  уходит с пометкой «отложено».
- Напоминает о незакрытой тревоге каждые `REMIND_MIN` минут (0 — не
  напоминать).
- Ходит в Telegram через прокси (`TG_PROXY`), например через xray/sing-box
  на самом роутере.

## Требования

- Keenetic с установленным **Entware** (на USB-накопителе или во встроенной
  памяти).
- Около 2 МБ места: пакеты `curl`, `ca-bundle`, `lighttpd`,
  `lighttpd-mod-cgi`. Установщик ставит их сам.
- Бот Telegram: создайте его у [@BotFather](https://t.me/BotFather) и
  напишите ему что-нибудь. ID чата подскажет [@userinfobot](https://t.me/userinfobot),
  а для группы — `https://api.telegram.org/bot<токен>/getUpdates`.

## Установка

В SSH-сессии Entware (по умолчанию порт 222, пользователь `root`):

```sh
opkg update && opkg install curl
curl -fsSLO https://raw.githubusercontent.com/YBakalenko/deadman/main/install.sh
sh install.sh
```

Без `curl` на роутере можно иначе: скачайте архив
<https://github.com/YBakalenko/deadman/archive/refs/heads/main.tar.gz> на
компьютер, перенесите на роутер, распакуйте и запустите `sh install.sh`
из распакованной папки. Тогда установщик возьмёт файлы рядом с собой и
ничего не будет скачивать, кроме пакетов Entware.

Чтобы ставить из своего форка, укажите его при запуске:
`DEADMAN_REPO=<логин>/<репозиторий> sh install.sh`.

Установщик поставит пакеты и файлы и задаст вопросы. На каждый вопрос можно
ответить пустой строкой, тогда останется значение в скобках.

| Вопрос | Пример |
|---|---|
| Как называть сервер в сообщениях | `Прод-сервер` |
| Токен бота | `123456:AA…` |
| ID чата | `123456789` или `-100…` для группы |
| Прокси для Telegram | пусто, или `socks5h://127.0.0.1:1080` |
| Через сколько минут без сигнала тревожить | `15` |
| Порт приёма на роутере | `8089` |
| Внешний адрес (KeenDNS) | `https://deadman.myname.keenetic.pro` |
| Адреса для проверки | `https://example.com https://example.com/health` |
| Напоминать каждые N минут | `60` |

В конце установщик покажет **адрес сигнала** вида
`https://deadman.myname.keenetic.pro/beat/Xy7…`. Держите его в секрете: по
нему кто угодно может «оживить» сервер. Повторно адрес покажет `deadman url`.

Повторный запуск `install.sh` или команда `deadman update` обновляют программу
и сохраняют настройки.

## KeenDNS: как сделать приёмник доступным снаружи

Сервер должен дотянуться до роутера из интернета. Проще всего через KeenDNS,
с HTTPS и сертификатом от Keenetic.

1. Веб-интерфейс роутера → **Сетевые правила → Доменное имя**. Если имени
   ещё нет, зарегистрируйте, например `myname.keenetic.pro`.
2. Там же → **Доступ к веб-приложениям домашней сети → Добавить**:
   - имя: `deadman`, получится `deadman.myname.keenetic.pro`;
   - устройство: сам роутер, его адрес в домашней сети (обычно `192.168.1.1`);
   - порт: `8089` (или ваш из настройки);
   - доступ: **разрешён без авторизации**. Защищает адрес сигнала со
     случайным ключом, а не пароль Keenetic: отправитель не умеет вводить
     пароль.
3. Режим KeenDNS «Через облако» работает и без белого IP. При белом IP
   можно выбрать прямой доступ.
4. Проверка с компьютера **вне домашней сети** (из дома обращение к своему
   KeenDNS часто не проходит, и это ничего не говорит о доступности снаружи):
   ```sh
   curl -i https://deadman.myname.keenetic.pro/beat/<ключ>   # 200 ok
   curl -i https://deadman.myname.keenetic.pro/beat/wrong    # 404
   ```
5. Укажите этот адрес в настройке: `deadman setup`, поле «Внешний адрес».

⚠️ **Порт HTTPS бывает не 443.** Если провайдер закрыл 443 или он занят,
Keenetic отдаёт KeenDNS по HTTPS на **8443**: `http://…` перенаправляет на
`https://…:8443/`. Тогда внешний адрес — `https://deadman.myname.keenetic.pro:8443`.

⚠️ **Корень домена — это веб-интерфейс роутера.** Адрес без поддомена
(`https://myname.keenetic.pro/beat/…`) попадёт в админку Keenetic, а не в
deadman. Нужен поддомен веб-приложения из шага 2.

Приёмник слушает адрес роутера в домашней сети (`br0`) и петлю `127.0.0.1`:
через петлю к нему ходит сам KeenDNS. WAN приёмник не слушает, наружу его
выводит только KeenDNS. **Порт 8089 на роутере из интернета открывать не
нужно.**

## Отправитель: что настроить на сервере

### Alertmanager (Prometheus)

Правило, которое горит всегда:

```yaml
groups:
  - name: deadman
    rules:
      - alert: Watchdog
        expr: vector(1)
        labels:
          severity: heartbeat
        annotations:
          summary: Сигнал «жив» для внешнего наблюдателя
```

Маршрут и получатель в `alertmanager.yml`:

```yaml
route:
  routes:
    - matchers: [ severity = "heartbeat" ]
      receiver: deadman
      group_wait: 0s
      group_interval: 1m
      repeat_interval: 5m      # чаще, чем BEAT_TIMEOUT_MIN, с запасом
      continue: false

receivers:
  - name: deadman
    webhook_configs:
      - url: https://deadman.myname.keenetic.pro/beat/<ключ>
        send_resolved: false
        max_alerts: 1
```

Тревога придёт и тогда, когда сервер жив, но умер сам Prometheus или
Alertmanager. Это тоже повод узнать.

### Любой сервер — cron

```sh
* * * * * curl -fsS -m 10 -o /dev/null https://deadman.myname.keenetic.pro/beat/<ключ>
```

## Команды

| Команда | Что делает |
|---|---|
| `deadman setup` | Задать настройки и перезапустить |
| `deadman start` / `stop` / `restart` | Управлять приёмом и сторожем |
| `deadman status` | Работает ли, когда пришёл последний сигнал, какие тревоги открыты |
| `deadman url` | Показать адрес сигнала |
| `deadman test` | Отправить пробное сообщение в Telegram |
| `deadman check` | Выполнить одну проверку сейчас |
| `deadman log [-f]` | Показать журнал |
| `deadman update` | Обновить из репозитория |
| `deadman uninstall [--purge]` | Удалить (`--purge` — вместе с настройками) |

Автозапуск при старте Entware — `/opt/etc/init.d/S99deadman`.

## Настройки

Файл `/opt/etc/deadman/deadman.conf` (права 600). После ручной правки
выполните `deadman restart`.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `NAME` | `Сервер` | Имя в сообщениях |
| `TG_TOKEN`, `TG_CHAT_ID` | — | Бот и чат для тревог |
| `TG_PROXY` | — | Прокси для Telegram, формат curl `-x` |
| `BEAT_TIMEOUT_MIN` | `15` | Сколько минут без сигнала — уже тревога |
| `LISTEN_ADDR` | адрес `br0` | Где слушать приём |
| `LISTEN_PORT` | `8089` | Порт приёма |
| `PUBLIC_BASE` | — | Внешний адрес для `deadman url` |
| `CHECK_URLS` | — | Адреса для проверки, через пробел; ответ 2xx/3xx — норма |
| `URL_FAILS` | `3` | Сколько неудач подряд считать отказом адреса |
| `INET_HOSTS` | `77.88.8.8 1.1.1.1` | Кого пинговать, чтобы понять, есть ли интернет у самого роутера |
| `REMIND_MIN` | `60` | Напоминание об открытой тревоге, мин; 0 — выкл. |
| `INTERVAL_SEC` | `60` | Как часто проверять |

Ключ сигнала хранится в `/opt/etc/deadman/beat.token`. Чтобы сменить ключ,
удалите файл и выполните `deadman setup`, затем пропишите новый адрес у
отправителя.

## Если что-то не так

| Что видно | Что проверить |
|---|---|
| Сразу после установки «сигнал не приходил ни разу» | Отправитель не настроен или шлёт не на тот адрес. Проверьте `curl` снаружи (раздел KeenDNS) |
| `deadman test` пишет, что Telegram не принял сообщение | Токен, ID чата, писали ли вы боту; доступ к `api.telegram.org` с роутера. Если доступа нет, задайте `TG_PROXY` |
| Тревоги приходят пачкой после отключения света дома | Так быть не должно: после возврата сети отсчёт идёт заново. Пришлите `deadman log` |
| Порт занят | Смените `LISTEN_PORT` в `deadman setup` и в KeenDNS |
| Снаружи 404 на верный ключ | Сравните ключ с `deadman url`. Убедитесь, что KeenDNS ведёт на тот же порт |
| Снаружи 502 Bad Gateway, а с роутера `curl http://192.168.1.1:8089/beat/wrong` даёт 404 | KeenDNS ходит к приложению через `127.0.0.1`. Версии до 1.0.1 петлю не слушали — обновитесь: `deadman update` |
| Снаружи открывается страница входа в роутер | Адрес без поддомена или веб-приложение KeenDNS не создано (раздел KeenDNS) |

Журналы: `/opt/var/log/deadman.log` (сторож) и
`/opt/var/log/deadman-httpd.log` (приём).

## Безопасность

- Наружу открыт ровно один путь, `/beat/<ключ>` с 32 случайными знаками.
  Всё остальное отвечает 404.
- Тело запроса не разбирается и не хранится: записывается только время
  сигнала.
- Токен бота лежит в файле с правами 600. На время отправки он попадает в
  аргументы `curl`, на роутере его видит только root.
- Штатный экземпляр lighttpd Entware установщик не трогает, если тот уже
  работал. Иначе выключает только его автозапуск, чтобы он не занял порт.
